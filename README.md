# Runespeak 채팅 번역

월드 오브 워크래프트를 하다가 외국어 채팅이 올라오면, 그 줄을 한국어로 옮겨 게임 채팅창과 똑같은 자리에 겹쳐 보여 주는 Mac 앱입니다. 반대로 내가 하고 싶은 말을 적으면 상대 언어의 게임 말투로 바꿔 클립보드에 담아 줍니다.

Swift로 쓴 네이티브 앱이고(macOS 14 이상, Apple Silicon), 외부 라이브러리는 쓰지 않습니다.

## 어떻게 동작하나

```
게임 창의 채팅창 사각형 ──(macOS 화면 캡처)──▶ 글자 인식(Vision) ──▶ 새로 올라온 줄 골라내기
        ──▶ 사전에서 이 줄에 나온 게임 이름·줄임말 찾기 ──▶ AI에 번역 요청 ──▶ 채팅창 위에 겹쳐 표시
```

쓰기 전에 확인할 전제 세 가지:

1. **입력 자료는 화면 그림뿐입니다.** 채팅창으로 잡아 둔 사각형의 캡처에서 글자를 인식합니다. 게임 프로세스나 게임 폴더는 열어 보지 않고, 키보드·마우스를 대신 눌러 주는 기능도 없습니다. 번역된 말을 채팅에 넣는 ⌘V도 사용자가 직접 누릅니다.
2. **인식한 채팅 글은 번역 서버로 나갑니다.** 받는 곳은 설정에서 선택한 AI의 운영사(Anthropic, OpenAI, Google 중 하나)이며, 그 AI의 키를 등록하지 않았다면 무료 번역 서비스 MyMemory입니다. 번역 요청 말고는 어디로도 자료를 보내지 않습니다. AI 키와 채팅 기록은 이 Mac의 데이터 폴더에 평문으로 남으니(아래 「저장 위치」), 백업본을 공유하거나 Mac을 넘길 때 그 폴더가 딸려 가지 않게 하세요.
3. **팬이 만든 도구입니다.** Blizzard Entertainment의 제품이 아니고 검수나 보증을 받은 적도 없습니다. 게임 약관에 비추어 써도 되는지는 쓰는 사람이 판단해야 하며, 그 결과도 쓰는 사람이 집니다.

## 설치

Xcode 또는 Swift 툴체인이 있는 Mac에서 저장소를 받은 뒤:

```sh
scripts/build-app.sh
open build/Runespeak.app
```

스크립트는 릴리스 빌드를 만들고, `data/`의 사전 파일을 앱 안에 넣고, ad-hoc 서명을 합니다. 새 버전은 같은 방법으로 다시 만들어 바꿉니다. 소스가 바뀐 뒤 다시 만들면 서명이 달라져 macOS가 화면 기록 허용을 한 번 더 요구합니다. 이때 시스템 설정에는 예전 빌드의 스위치가 켜진 채로 남아 있을 수 있습니다(아래 「문제 해결」).

### 다른 Mac에 나눠 주기

```sh
scripts/build-dmg.sh              # 앱을 새로 만든 뒤 build/Runespeak.dmg로 묶기
scripts/build-dmg.sh --no-build   # 이미 만들어 둔 build/Runespeak.app을 그대로 묶기
```

`build/Runespeak.dmg`에는 앱, `Applications` 폴더로 가는 바로가기, 처음 실행 안내(`먼저 읽어 주세요.txt`) 세 가지만 들어갑니다. AI 키, 설정, 채팅 기록은 앱 바깥의 데이터 폴더(아래 「저장 위치」)에 있어서 함께 가지 않습니다. 받는 Mac도 macOS 14 이상의 Apple Silicon이어야 합니다.

받은 사람은 dmg를 열어 Runespeak을 `Applications`로 끌어다 놓고, 응용 프로그램 폴더에서 엽니다. Apple의 공증을 받지 않은 ad-hoc 서명 앱이라 첫 실행은 macOS가 막습니다. macOS 15 이상에서는 시스템 설정 → 개인정보 보호 및 보안 → [그래도 열기]로, macOS 14에서는 앱을 Control-클릭 → [열기]로 한 번 허용하면 됩니다. 그 뒤는 아래 「처음 실행할 때 할 일」과 같습니다. AI 키는 받은 사람이 자기 것을 앱의 [설정]에 직접 넣어야 하며, 키를 메신저나 메일로 주고받지 마세요.

## 처음 실행할 때 할 일

| 순서 | 할 일 | 설명 |
|---|---|---|
| 1 | 화면 기록 허용 | 시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 녹음에서 Runespeak의 스위치를 올립니다. 허용은 앱을 새로 띄워야 적용되므로 기록 창의 [다시 실행]을 누릅니다. |
| 2 | 채팅창 위치 잡기 | 게임을 띄워 둔 상태에서 [채팅창 위치 잡기]를 누르고, 게임 화면 위에 채팅창을 감싸는 사각형을 그립니다. 누가 어느 채널에서 말했는지는 줄 맨 앞의 `[길드]` 같은 채널 이름으로 알아내므로, 그 부분이 사각형 안에 들어와야 합니다. 게임 창 크기를 바꿨다면 같은 버튼으로 다시 잡습니다. |
| 3 | AI 키 등록 | [설정] → AI 연결에서 AI를 하나 고르고 키를 붙여 넣습니다. 키가 없으면 MyMemory가 대신 번역합니다. MyMemory는 게임 사전을 참고하지 못하는 범용 번역이고 하루 사용량에 상한이 있습니다. |

Runespeak을 켰을 때 게임이 같은 데스크탑에 보이고 있으면 2번 화면이 바로 뜹니다. 게임이 전체 화면 전용 공간에 있거나 접혀 있으면 버튼을 누를 때까지 기다립니다.

## 사용법

**읽기.** 번역 대상 채널의 외국어 줄은 게임 채팅창 자리에 한국어로 겹쳐 나오고, 기록 창에도 원문과 함께 남습니다. 겹침 창 위쪽의 탭(길드 / 파티/공격대 / 귓속말 / 일반/외침 / 공개 채널)으로 어느 채널을 번역할지 켜고 끕니다. 줄이 많이 올라오는 일반/외침과 공개 채널은 꺼진 채로 시작합니다. 탭을 새로 켜면 화면에 남아 있던 그 채널의 최근 30줄까지 거슬러 번역합니다. 똑같은 광고가 반복되면 처음 한 번만 요청하고 이후에는 그 결과를 재사용합니다. 번역 모델이 원문을 그대로 돌려준 줄(이름뿐인 줄, 뜻 없는 소리, 읽다 만 글자처럼 옮길 것이 없다고 본 줄)은 번역된 것으로 치지 않고 게임에 나온 그대로 둡니다. 그런 줄을 다시 요청하지는 않으며(같은 글이 또 올라와도 마찬가지), 필요하면 우클릭해 [다시 번역]을 쓸 수 있습니다. [다시 번역]도 원문을 그대로 돌려주면 줄은 원문 그대로 두고, 모델이 덧붙인 설명(왜 옮길 것이 없는지)만 그 줄에 남깁니다. 앞부분이 가려져 뒷부분만 읽힌 줄(「… 뒷부분」)은 [다시 번역]할 수 없고, 전체 문장이 읽히면 번역됩니다.

**말하기.** 게임 안에서 보낼 말 입력창을 열어 한국어로 적고 ↩를 누르면 번역 결과가 클립보드에 담깁니다. 게임 채팅 입력줄을 열어 ⌘V로 붙이면 됩니다. `/ㅎ 안녕하세요`, `/파티 잠시만요`처럼 한글 명령어나 한글 자판 상태로 친 명령어로 시작하면, 명령은 어느 언어 클라이언트에서나 통하는 영어 명령(`/g`, `/p`)으로 바꾸고 뒤의 말만 번역합니다. 어느 언어로 옮길지는 [설정]의 「보낼 말의 언어」에서 고릅니다.

| 조작 | 하는 일 |
|---|---|
| ⌃⌥T | 겹쳐 보기 켜기/끄기 |
| ⇧↩ (게임 창이 활성일 때만) | 보낼 말 입력창 열기 |
| 채팅창 위에서 ⌥ 누르고 있기 | 겹친 번역을 잠시 걷고 원래 채팅 보기 |
| 번역된 줄 우클릭 → 다시 번역 | 더 정확한 모델로 그 줄만 새로 번역하고, 결과와 설명을 `corrections.tsv`에 적어 둠 (AI 키 필요) |
| 실패한 줄 우클릭 → 다시 시도 | 같은 모델로 한 번 더 요청. 키나 모델을 바꾸면 최근에 실패한 줄은 저절로 다시 보냄 |
| 채팅창 위치를 잡는 중 esc 또는 우클릭 | 잡기 그만두기 |
| 겹침 창의 빈 곳 우클릭 | 글자 크기, 번역 모델, AI 제공자, 보낼 말의 언어, 채팅창 위치 다시 잡기 |
| 메뉴 막대 아이콘 | 기록 창 열기, 겹쳐 보기 전환, 채팅창 위치 잡기, 보낼 말 번역, 설정, 종료 |

두 단축키는 [설정]에서 다른 조합으로 바꿀 수 있습니다. 겹침 창은 게임 창이 맨 앞에 있을 때만 떠 있고, 다른 앱으로 넘어가면 자동으로 내려갑니다. 기본 설정에서는 스크린샷이나 방송 화면에 겹친 번역이 찍히지 않습니다([설정] → 화면에서 바꿀 수 있습니다).

## AI 선택과 비용

| AI | 키를 만드는 곳 | 평소 번역 / 다시 번역에 쓰는 기본 모델 |
|---|---|---|
| Claude | <https://platform.claude.com/settings/keys> | Claude Haiku 5.5 / Claude Opus 5.5 |
| ChatGPT | <https://platform.openai.com/settings/organization/api-keys> | GPT-6 Luna / GPT-6.1 Sol |
| Gemini | <https://aistudio.google.com/api-keys> | Gemini 3.5 Flash-Lite / Gemini 4 Hydrogen |

- 키는 AI별로 따로 보관하며, 선택한 AI의 키가 있을 때만 그 AI가 번역합니다.
- 월 구독(ChatGPT Plus, Claude.ai, Gemini 앱)과 API는 별개 상품입니다. 위 콘솔에서 키를 만들고 결제 수단을 등록해야 하며, 요금은 번역한 분량에 따라 각 회사가 직접 청구합니다.
- [연결 확인]은 등록한 키로 모델 목록을 한 번 요청해 봅니다. 과금되지 않습니다.
- 실시간용 모델과 다시 번역용 모델을 따로 고릅니다. [모델 목록 새로 고침]으로 내 키가 쓸 수 있는 모델을 불러오거나, 모델 ID를 직접 적어 넣을 수 있습니다.
- 앱이 보여 주는 금액은 토큰 수에 공개 단가를 곱한 추정치입니다. 단가를 모르는 모델을 쓴 분량은 빠지고 「일부 모델 단가 미상」이라고 표시됩니다. 실제 청구 금액은 각 회사의 결제 화면에서 확인하세요.

## 사전

AI에게 채팅 줄과 함께 "이 줄의 이 낱말은 이런 뜻일 수 있다"는 참고 자료를 넘겨, 지명·던전·우두머리 이름이 공식 번역대로 나오게 합니다. 사전 파일은 저장소의 `data/`에 있고 빌드할 때 앱 안에 들어갑니다. 따로 내려받을 것은 없습니다.

| 파일 | 담긴 것 | 만드는 방법 |
|---|---|---|
| `official_names.{classic,retail}.tsv` | 지역, 인스턴스, 우두머리, 진영, 직업, 주문, 아이템 등의 한국어·영어 공식 이름 짝 | Blizzard 게임 데이터 표(공개 DB2 내보내기)의 koKR 값과 enUS 값을 행 ID로 맞붙여 `tools/build_dictionary.py`가 생성 |
| `chat_commands.{classic,retail}.tsv` | 채팅 종류별 슬래시 명령어의 모든 철자 | 같은 도구가 게임 데이터에서 생성 |
| `zone_places.{classic,retail}.tsv` | 지역마다 그 안에 있는 장소(하위 지역)의 한국어·영어 이름 | 같은 도구가 게임 데이터의 지역 표(AreaTable)에서 생성 |
| `abbreviations.{classic,retail}.tsv` | 채팅 줄임말과 은어, 뜻이 여럿이면 뜻마다 한 줄 | 손으로 작성 |
| `nicknames.tsv` | 공식 이름의 통용 약칭 (Undercity → UC) | 손으로 작성 |

형식은 모두 UTF-8 탭 구분 표이며 첫 줄이 열 이름, `#`로 시작하는 줄은 주석입니다. `classic`은 오리지널 계열 서버와 확장팩 클래식, `retail`은 본 서버에 쓰입니다. 클래식 클라이언트끼리 한국어 이름이 다른 경우에는 오리지널 쪽 이름 하나만 싣습니다.

**지역 채널의 장소 힌트** — 지역 이름이 붙는 채널(`1. 공개 - 타나리스`, `3. 수비 - 타나리스`, 영어 클라이언트의 `General - Tanaris`)에서 나온 줄에는, 그 지역의 장소 가운데 이름의 낱말이 줄에 들어 있는 것을 최대 3곳까지 그 줄에 붙여 넘깁니다. 줄에서 찾은 표현과 장소의 한국어·영어 이름이 함께 갑니다. 그 지역 사람끼리만 통하는 줄임 표현(모단 호수 채널의 `2 more for IE site`는 아이언밴드의 발굴현장)을 다른 지역의 이름으로 지어내지 않게 하려는 것입니다. 장소가 붙은 줄은 다른 줄과 섞지 않고 따로 한 번의 요청으로 보내며, 그 요청에만 장소 힌트를 읽는 법을 덧붙입니다. 한 줄에 붙은 장소가 같은 요청의 다른 줄 번역에 끼어드는 일을 막고, 장소가 없는 줄(거의 전부)은 장소 힌트가 생기기 전과 똑같이 번역되게 하려는 것입니다.

- 낱말의 앞 다섯 글자 이상만 적은 것(타나리스 채널의 `steamwh`)도 찾습니다.
- 장소의 종류를 가리키는 낱말(`site`, `harbor`, `tavern`처럼 네 지역 이상에서 장소 이름의 끝 낱말로 쓰이는 것)은 혼자서는 힌트가 되지 않습니다. 그 장소만의 낱말이 함께 있거나(`excav site`), 이름의 나머지를 줄인 2~4글자가 바로 앞에 있을 때(`IE site`)만 힌트가 됩니다. 그런 줄임 글자는 대문자로 적은 것만 봅니다(짧은 낱말은 무엇이든 어느 이름의 줄임으로 읽을 수 있어서 `one sec keep going` 같은 줄에 장소가 붙기 때문). 줄 전체가 대문자이거나 방위(`SE tower`)이면 줄임 글자로 보지 않고, 소문자로는 이름 낱말의 앞 네 글자(저습지 채널의 `whel site`)만 봅니다.
- 여러 장소가 함께 가진 낱말로 찾은 곳보다 그 장소에만 있는 낱말로 찾은 곳을 먼저 붙입니다.
- 흔한 낱말(`trade`, `old`, `keep`), 줄임말·이름 사전이 이미 설명한 낱말, 아이템·퀘스트 링크 안의 낱말로는 찾지 않습니다.
- 채널 이름의 지역을 화면에서 한 글자 잘못 읽었더라도 그렇게 읽힐 지역이 하나뿐이면 그 지역으로 봅니다.
- 지역이 붙지 않는 채널(거래, 파티찾기)과 길드·파티·일반 대화, `/me`로 적은 행동에는 장소 힌트가 없고, `zone_places` 파일이 없으면 이 힌트만 빠진 채 그대로 동작합니다.
- 장소 힌트로 [다시 번역]한 결과는 그 줄과 그 지역 채널의 기억에만 남기고 교정 예시(`corrections.tsv`)로는 저장하지 않습니다. 교정은 글만 보고 다시 쓰이므로 다른 지역의 같은 글에 이 지역 장소가 붙기 때문입니다.
- 같은 이름의 지역이 던전·공격대·시나리오 지도에 복사본으로 또 있으면(게임 데이터에는 이웃 지역의 장소를 거느린 `그늘숲`이 공격대 지도에 따로 있습니다) 필드 지도의 원래 지역 하나만 그 이름의 지역으로 봅니다.

**게임이 패치된 뒤 공식 이름 갱신**

```sh
python3 -I tools/build_dictionary.py            # 표를 내려받아 official_names, chat_commands, zone_places 재생성
python3 -I tools/build_dictionary.py --offline  # 이미 받아 둔 .cache/ 만으로 재생성
scripts/build-app.sh
```

도구는 시험용·미사용 행, 목록 머리글, 같은 영어 이름에 붙은 두 번째 한국어 이름을 걸러 내고 몇 줄을 버렸는지 출력합니다. `--dropped 파일` 을 주면 버린 행을 전부 적어 주므로 검토할 수 있습니다.

**줄임말·약칭 고치기** — `data/abbreviations.*.tsv`, `data/nicknames.tsv`를 편집기로 고치고 앱을 다시 만듭니다. 아래 명령으로 채팅 줄마다 AI에게 어떤 참고 자료가 나가는지 미리 볼 수 있습니다.

```sh
.build/debug/Runespeak --dictionary-check data 채팅줄.txt
```

파일의 한 줄은 본문만 적거나 `채널<TAB>보낸이<TAB>본문`으로 적습니다. 지역 채널의 장소 힌트까지 보려면 채널 뒤 대괄호 안에 게임에 보이는 채널 이름을 적습니다: `publicChannel[1. 공개 - 타나리스]<TAB>보낸이<TAB>본문`.

**앱을 다시 만들지 않고 이름 등록하기** — [설정] → 용어 사전 → [데이터 폴더 열기]로 열리는 폴더의 `my_terms.tsv`에 적습니다. 처음 열 때 쓰는 법이 적힌 파일이 만들어집니다. `nicknames.tsv`와 같은 탭 구분 표입니다.

```
korean	english	aliases
오그리마	Orgrimmar	OG, 오그
검은바위 나락	Blackrock Depths	BRD, 나락 (the dungeon under Blackrock Mountain)
```

셋째 칸에는 같은 것을 가리키는 다른 표기를 쉼표로 이어 적고, 괄호 안에는 그 표기가 어떤 때 이 뜻인지 적어 둘 수 있습니다. 영문 대문자 두 자뿐인 표기는 채팅에도 대문자로 적혀 있을 때만 이름으로 칩니다. 이 파일의 내용은 앱에 든 사전보다 우선하며, Runespeak을 다시 실행해야 읽힙니다.

[다시 번역]의 결과는 같은 폴더의 `corrections.tsv`(원문, 번역, 설명의 세 칸)에 쌓이고, 비슷한 줄이 다시 나오면 그 번역을 따릅니다.

## 문제 해결

- **「대기 중 · 화면에서 게임 채팅창을 찾을 수 없습니다」** — 게임이 꺼졌거나 접혀 있거나, 잡아 둔 사각형이 지금의 게임 창 밖에 있습니다. 창 크기나 해상도를 바꿨다면 채팅창 위치를 다시 잡으세요.
- **스위치를 켜 두었는데도 「화면 기록이 허용되어 있지 않습니다」가 뜸** — 앱을 새 버전으로 바꾼 뒤에 생깁니다. macOS는 화면 기록 허용을 앱의 서명에 묶어 두는데, ad-hoc 서명은 빌드마다 달라서 설정에 켜져 있는 항목은 예전 빌드의 것입니다. 시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 녹음에서 Runespeak의 스위치를 껐다가 다시 켜거나, 항목을 골라 [−]로 지운 뒤 앱을 열어 새로 허용하고 [다시 실행]을 누릅니다. 터미널에서 `tccutil reset ScreenCapture local.runespeak`을 실행해 항목을 지워도 됩니다.
- **「게임 화면을 찍지 못했습니다 (…)」** — 게임은 보이는데 macOS가 캡처를 거부한 경우입니다. 괄호 안의 오류 이름이 `errors.log`에도 남습니다. 화면 기록 허용이 풀리지 않았는지 먼저 확인하세요.
- **이름 0개, 줄임말 0개로 나옴** — `swift build`로 만든 실행 파일을 직접 띄우면 사전이 들어 있지 않습니다. `scripts/build-app.sh`가 만든 앱을 실행하세요. 빠진 파일 이름은 `errors.log`에 적힙니다.
- **채팅창 뒤로 캐릭터가 지나갈 때 번역이 몇 초 늦음** — 머리 위 이름이 채팅 줄을 가리면 그 줄이 제대로 읽힐 때까지 최대 3.5초(기본 캡처 간격 기준) 기다렸다가 내보냅니다. 그때까지도 못 읽으면 읽힌 만큼만 먼저 보여 줍니다: 첫 줄이 가려진 메시지는 아랫줄만 보낸 사람 없이 「… 뒷부분」으로(이런 조각은 따로 번역하지 않습니다), 중간 줄이 계속 바뀌어 읽히는 메시지는 그 자리를 「…」로, 한 줄짜리 메시지는 「(다른 글자에 가려 읽지 못한 줄)」로 표시합니다. 가리던 이름이 비켜나거나 채팅이 올라가 그 줄이 제대로 읽히면, 먼저 보여 준 줄이 온전한 메시지로 바뀌고 번역은 그때 한 번 붙습니다 (`chat_history.txt`에는 두 줄이 모두 남고, 조각은 `(조각)`, 자리를 대신한 줄은 `(다시 읽음)`으로 표시됩니다). 이름이 줄 끝에 바짝 붙어 채팅 글자처럼 또렷하게 읽힌 경우에는 처음에 이름까지 함께 나올 수 있는데, 이름이 비켜나고 약 14초 안에 그 줄이 두 번 연달아 이름 없이 읽히면 같은 방식으로 고쳐집니다.
- **게임의 메뉴가 채팅창 위에 떠 있는 동안 새 줄이 안 나옴** — 채팅 탭 메뉴(탭을 우클릭하면 뜨는 메뉴)의 글자가 채팅 줄을 가리는 동안에는 읽기를 멈춥니다. 메뉴를 닫으면 그사이 올라온 줄 가운데 아직 화면에 있는 것이 차례대로 한 번씩 나옵니다. 메뉴가 떠 있는 동안 올라왔다가 화면 밖으로 밀려난 줄은 읽지 못합니다. 메뉴 항목 이름(「글자 크기」, 「배경 설정」 …)이 들어간 채팅은 채팅으로 읽습니다. 앱이 알아보는 것은 이 탭 메뉴뿐입니다. 다른 메뉴(이름 우클릭 메뉴 등)나 창, 툴팁이 채팅 줄을 가리고 있을 때는 읽기를 멈추지 않습니다. 그래서 그것이 떠 있는 동안에는 가려진 줄이 그 위의 글자와 섞여 읽혀, 아무도 하지 않은 말이 몇 줄 목록에 들어갈 수 있습니다. 그때 가려져 있던 실제 채팅도 잘리거나 메뉴 글자가 섞인 채로, 또는 「(다른 글자에 가려 읽지 못한 줄)」로 남을 수 있으며, 닫은 뒤에 고쳐지지 않는 경우가 있습니다. 채팅창 배경이 불투명이든 반투명이든 같습니다.
- **특정 이름이 계속 틀림** — `my_terms.tsv`에 이름을 등록하거나, 그 줄을 우클릭해 [다시 번역]으로 교정 기록을 남기세요.

## 개발할 때

```sh
swift build && swift test
.build/debug/Runespeak --ocr-selftest        # 합성한 채팅 그림으로 글자 인식 점검
.build/debug/Runespeak --pipeline-selftest   # 인식 → 새 줄 추적 → 번역 대기열까지 통째로 점검
.build/debug/Runespeak --ocr-selftest --image 스크린샷.png [enUS]   # 실제 스크린샷으로 인식 결과 보기
.build/debug/Runespeak --dictionary-check data [채팅줄.txt]         # 사전 건수, 읽는 시간, 줄별 참고 자료 (줄 형식은 --translate-check와 같음)
.build/debug/Runespeak --replay-image 스크린샷.png [둘째.png ...] [--crop x,y,w,h] [--frames N] [--locale koKR|enUS]
                                             # 저장한 스크린샷을 인식 → 새 줄 추적까지 흘려 보고, 읽은 줄과 내보낸 메시지를 출력
                                             # 여러 장을 주면 같은 자리를 차례로 찍은 화면으로 보고 이어서 흘림
                                             # --trace: 인식 단계마다 어느 모델이 무엇을 읽었고 줄마다 무엇을 골랐는지 stderr로 출력
.build/debug/Runespeak --translate-check 채팅줄.txt [--data data] [--batch N] [--flavor classic|retail] [--model 모델ID] [--context 앞대화.txt]
                                             # 저장된 설정·키·모델로 실제 번역 요청을 보내 "원문 => 번역"과 토큰 비용을 출력 (요금이 나감)
                                             # 한 줄에 메시지 하나: 본문만, 또는 "채널<TAB>보낸이<TAB>본문" (채널: guild, party, yell, whisper, publicChannel ...)
                                             # 채널 뒤 대괄호에 게임의 채널 이름을 적을 수 있음: "publicChannel[1. 공개 - 타나리스]<TAB>보낸이<TAB>본문"
                                             # (그 지역의 장소 힌트가 함께 나감. 이름을 적지 않은 publicChannel 줄은 "1. 공개 - 스톰윈드"로 봄)
                                             # 요청마다 함께 나간 힌트를 "— 요청 N 힌트: …"로 출력 (이름·줄임말 등은 개수, 장소는 붙어 나간 줄 번호·지역·줄에서 찾은 표현과 함께 전부)
                                             # 장소가 붙은 줄은 앱과 같이 따로 요청하므로 --batch 한 묶음이 요청 둘이 될 수 있음 (요청마다 묶음의 몇 번째 줄인지 출력, 장부에도 요청 수대로 셈)
                                             # --model: 설정된 모델 대신 그 모델로. --context: 같은 형식의 파일을 요청마다 앞 대화로 함께 보냄
                                             # "=?"로 나온 줄은 모델이 원문을 그대로 돌려준 줄 (앱에서는 번역으로 치지 않음)
                                             # 사용량 기록과 채팅 기록에는 아무것도 쓰지 않음
.build/debug/Runespeak --translate-check 채팅줄.txt --ledger 장부.tsv --max-requests 120 --max-usd 0.30 [--agent 이름] [--run 실행이름]
                                             # 여럿이 한 예산을 나눠 쓸 때: 장부(실행 이름<TAB>실행한 쪽<TAB>요청 수<TAB>달러)의 합계에
                                             # 이번 실행의 예상치를 더해 한도를 넘으면 시작하지 않고, 도중에 한도에 닿으면 멈추며, 요청 하나가 끝날 때마다 쓴 만큼 한 줄을 덧붙임
                                             # (도중에 멈춘 실행도 보낸 만큼은 장부에 남음. 저장된 키 파일은 읽기만 하고 건드리지 않음)
                                             # 예상 비용은 넉넉하게 잡으므로(첫 요청은 캐시 쓰기 값) 한도 가까이에서는 실제로 들어갈 실행도 거절될 수 있음
```

소스는 `Sources/RunespeakCore`(채팅 추적, 사전, 번역 요청 — 화면과 무관한 부분)와 `Sources/Runespeak`(캡처, 겹침 창, 설정 화면)로 나뉘고, 단위 테스트는 `Tests/RunespeakCoreTests`에 있습니다. 테스트는 네트워크를 쓰지 않습니다.
